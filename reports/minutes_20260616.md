# Unisolar — Project Minutes (June 16, 2026)

## Objective
Correct residual positive bias in satellite-to-ground GHI correction for the ZINDI Solar Challenge using a stacking ensemble, with special attention to spatial generalization across unseen Sahelian stations.

---

## Pre-LSTM Phase (Weather Models & Stacking Ensemble)

### Station Bias Bug — Root Cause & Fix
- **Bug**: During GroupKFold CV, validation groups correspond to unseen stations with no known `station_bias`. Old code left `station_bias=NaN` in validation folds. Tree models silently learned station-specific splits from real bias values in training data, producing non-generalizing trees.
- **Impact**: When `fillna(0.0)` was applied (to fix Ridge's NaN intolerance), results inflated dramatically: XGBoost jumped from 140 to 148, RF from 139 to 147. The splits had learned station-specific patterns that broke when validation received zeros.
- **Fix**: Zero `station_bias` for **both** training and validation during k-fold. No station-specific information leaks. True per-station bias is only used during final full-data retraining.
- **Result**: Honest 5-fold CV numbers ~140-143 W/m² RMSE.

### Target Selection
- **kt rejected**: `kt = GHI / clear_sky_ghi` amplifies cloudy-day errors (`error = clear_sky_ghi × error_in_kt`, where clear_sky_ghi ≫ satellite GHI).
- **Ratio adopted**: `ratio = GHI_ground / GHI_satellite`, bounded [0.0, 3.0]. Error propagates proportionally to satellite signal, which is already low on cloudy days. Both targets produce similar k-fold RMSE but ratio is better-behaved.

### Feature Engineering
- **AOD at 550nm**: Added from NASA POWER `power_AOD_55` (sourced from MERRA-2). Fallback 0.15. Contributed ~+1.8 W/m² on held-out benchmark.
- **Cloud variability features** (4 new):
  - `ghi_satellite_lag2`: GHI at t-6h
  - `clearness_index_lag1`: Cloud attenuation factor at t-3h
  - `clearness_index_std_3h`: Std dev over t, t-1, t-3h (broken vs uniform clouds)
  - `clearness_index_delta`: Rate of cloud change (clearing vs clouding over)
- **Improvement**: Stacking 138.75 → 138.37 (-0.38), Ridge 142.95 → 141.30 (-1.65).

### Model Selection
- **Stacking ensemble**: XGBoost + RandomForest + Ridge (via `StandardScaler + Ridge(alpha=10.0)`)
- **LightGBM dropped**: 99.5% correlation with XGBoost on identical features. No diversity gain.
- **XGBoost meta-model** trained on 3 base model ratio predictions.
- **Forward-chaining**: `--forward-chaining N` flag using TimeSeriesSplit (expanding windows) available but not primary metric.

## LSTM Phase (Temporal Deep Learning)

### Motivation
Tree models see each row independently — they cannot learn cloud evolution patterns beyond the single lag-3h feature (`ghi_satellite_lag1`). An LSTM with a 24h lookback window (8 steps × 3h) can model cloud advection, clearing/clouding rates, and diurnal cycle phase shifts.

### Architecture
- **Type**: Bidirectional LSTM, 1 layer, 32 hidden dims
- **Input**: 21 features (subset of the 36 tree features — no station_bias, no engineered interaction terms)
- **Sequence**: 8 timesteps × 3h = 24h window
- **Output**: Sigmoid × 3.0 → ratio bounded [0, 3]
- **Training**: AdamW, ReduceLROnPlateau, early stop after 8 stale epochs, batch size 64
- **Infrastructure**: Pure PyTorch CPU on M3 Mac (16 GB)

### LSTM Proof-of-Concept (Single Fold)
Initial single-fold test (fold 1):
- LSTM: **132.83**
- XGBoost (same fold): **133.46**
- LSTM slightly ahead. Full 5-fold was killed by macOS memory pressure due to inline script size.

### Full 5-Fold CV Results (Completed Successfully)
After separating LSTM and XGBoost into standalone processes:

| Fold | XGBoost | LSTM | Δ |
|---|---|---|---|
| 1 | 133.46 | 134.41 | −0.95 |
| 2 | 137.17 | **134.64** | +2.53 |
| 3 | 145.87 | **143.35** | +2.52 |
| 4 | 141.63 | **136.81** | +4.82 |
| 5 | 149.07 | **144.15** | +4.92 |
| **Mean** | **141.44 ± 5.65** | **138.67 ± 4.24** | **+2.77** |

LSTM beats XGBoost on **4/5 folds** with lower cross-fold variance (±4.24 vs ±5.65). This is with a minimal architecture (32 dim, 1 layer) — no hyperparameter tuning has been done.

### Why LSTM Works
- Temporal structure: 8 timesteps capture 24h of cloud evolution. XGBoost only sees a single lag-3h snapshot.
- Sequence normalization removes per-station mean/scale shifts naturally.
- Lower variance suggests better spatial generalization across unseen stations.

## Way Forward

### 1. LSTM in Stacking Ensemble (Highest Impact, ~1-2h)
Add LSTM as a 4th base model in the stacking ensemble. Given LSTM (138.67) beats all 3 current base models individually, and stacking already extracts value from diversity, this could push the ensemble below 138 W/m² k-fold.

### 2. Station Quality Audit (Zero-Cost, ~30min)
3 faulty stations mentioned previously. Reducing noise in training labels is the highest-leverage zero-cost improvement — it benefits every model equally.

### 3. Bigger LSTM (Tuning, ~2-3h)
- Test 64→128 hidden dims
- 2-layer bidirectional
- Longer sequences (16 timesteps = 48h)
- Higher epochs with better early stopping
- Systematically find optimal architecture

### 4. MERRA-2 Aerosol Speciation (Infrastructure, ~1h setup)
Current `power_AOD_55` already comes from MERRA-2 (via NASA POWER). The upgrade is to fetch hourly aerosol components (dust, sea salt, BC, OC, sulfate) directly from GES DISC MERRA-2 (M2T1NXAER). Requires NASA Earthdata account setup. Likely most helpful for Sahel stations (dust) and biomass burning season (BC/OC).

### 5. GT Temporal Averaging
NASA POWER GHI is a 3-hour average. Ground truth is instantaneous. Averaging GT measurements ±1.5h around each POWER timestamp would better align the targets with the predictors. Modest improvement, zero cost.
